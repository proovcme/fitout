# FITOUT Simulator

Циничная партийная ролевая игра о ремонте офисов и экономический симулятор
генподрядчика. Игрок начинает в цоколе БЦ «Банкрот», меняет PlayStation 5 на
принтер, собирает команду таких же оптимистов и пытается стать Королём
Генподряда.

Публичная версия: [fitout.ovc.me](https://fitout.ovc.me/).

Текущая версия — `0.1.0`. Это вертикальный срез, а не завершённая игра. В
репозитории одновременно развиваются два связанных контура:

1. **Приключение на стройке** — управляемый герой ходит по 2.5D-объекту,
   разговаривает, осматривает проблемы, отдаёт команды и буквально меняет
   площадку.
2. **Компания-генподрядчик** — портфель объектов, сотрудники, подрядчики,
   график, материалы, приёмка, платежи, кредиты, кассовые разрывы и развитие
   штаба.

Главное направление разработки — перенос управленческой глубины второго
контура в пространство первого: меньше таблиц, больше решений, которые видны
на стройке.

## Во что уже можно играть

Основная игровая сцена:

```text
/prototypes/fitout-chapter-one.html
```

Первая глава начинается на действующем объекте. Семён отправляет героя за
поверенной рулеткой. Игрок должен открыть ящик, забрать инструмент, измерить
проём, оформить заказ в снабжении, указать правильный размер двери, дождаться
монтажа и проверить результат.

Параллельно площадка живёт своей жизнью: сотрудники ходят по маршрутам,
занимаются профильной работой, разговаривают, бездельничают, пишут в чат и
создают новые производственные поводы для беспокойства.

## Управление

### Компьютер

| Действие | Управление |
| --- | --- |
| Ходьба | `WASD` или стрелки |
| Бег | `Shift` + направление |
| Контекстное действие | `E` |
| Рискованно «Порешать» | `R` |
| Журнал, задачи, навыки и инвентарь | `J` |
| Закрыть верхнее окно | `Esc` |
| Показать маршрутную сетку разработчика | `N` |
| Идти в точку | клик по полу |
| Подойти и взаимодействовать | клик по человеку или объекту |
| Масштаб камеры | колесо мыши |

### iPad

- Касание пола задаёт точку движения.
- Касание персонажа или объекта отправляет героя к цели.
- Крупная контекстная кнопка появляется, когда действие доступно.
- Интерфейс учитывает системные безопасные зоны экрана.

Телефоны пока намеренно не поддерживаются: вместо сжатого и непригодного
интерфейса игра показывает сообщение с просьбой открыть её на компьютере или
iPad.

## Основной игровой цикл

```text
заметить проблему
        ↓
физически дойти до места
        ↓
осмотреть объект или поговорить с участником
        ↓
выбрать специалиста, приказ или рискованный обход
        ↓
увидеть, как работа выполняется на площадке
        ↓
принять результат либо получить дефект и последствия
        ↓
деньги, опыт, отношения, новая проблема
```

Игрок не управляет рабочими как отрядом RTS. Он управляет руководителем
проекта и действует через разговоры, прорабов, чат, снабжение и личное
присутствие. Чем больше проблем одновременно, тем важнее выбрать, куда бежать
самому, а что доверить команде.

## Механики игровой сцены

### Контекстное взаимодействие

`ContextActions` ищет ближайшее доступное действие с учётом расстояния,
состояния объекта и квеста. Ящик можно открыть, содержимое — забрать, проём —
измерить, с персонажем — поговорить, а установленную дверь — открыть. Клик по
интерактивному объекту объединяет движение и действие: герой сначала подходит,
затем автоматически активирует выбранный контекст.

### Физическая стройка

`PhysicalConstruction` хранит реальные технологические фронты:

- демонтаж;
- перегородки;
- инженерия;
- отделка;
- мебель.

У каждой работы есть зависимости, длительность, качество, контроль, ошибки и
визуальное состояние. Стена не считается построенной от изменения процента:
на сцене появляются стойки, панели, сети, отделка и мебель. Жёсткие физические
зависимости нельзя обойти штатной командой. Рискованный запуск возможен только
там, где механика сознательно допускает работу «на свой страх».

### Проблемы как «бой»

Строительный бой — это ограниченная по времени проблема, а не стрельба.
Например:

- мусор мешает проходу и ухудшает качество;
- незаконченная электрика оставляет опасный кабель;
- сантехническая течь создаёт лужу;
- лужа рядом с кабелем превращается в комбинированную аварию;
- работа без контроля получает риск дефекта;
- следующая бригада может начать поверх непредъявленного результата.

`SiteAttention` следит, какие фронты игрок бросил без внимания. Если долго не
вмешиваться, площадка сама принимает решения — обычно формально логичные и
практически катастрофические.

### Режиссёр первого дня

`DayOneDirector` не кидает случайные модальные события. Он детерминированно
собирает смену из 25 причинных эпизодов и управляет ритмом:

1. наблюдение — люди предупреждают о слабых сигналах;
2. давление — мусор расползается, свет моргает, команды понимают буквально;
3. кризис — заказчик идёт к проблеме, вода встречается с кабелем, технадзор
   находит закрытые работы;
4. передышка — находится сертификат, заказчика задерживает турникет, рабочий
   сам исправляет ошибку.

За смену одновременно существует не больше одного крупного кризиса. После его
разрешения режиссёр обязан дать передышку. События проявляются через сцену,
персонажей и чат: меняются свет, материалы, мусор, лужа, маршрут заказчика и
состояние фронтов.

Режиссёр запоминает стиль игрока: личный контроль, делегирование, крик,
дипломатию или «Порешать». Авторитет и доверие влияют на последующие приказы.
Крик может ускорить работу сейчас, но снижает доверие; нормальное
делегирование постепенно делает Семёна самостоятельнее.

«Порешать» — заметная рискованная способность с перезарядкой. Она может снять
кризис, купить немного времени или породить новый фронт объяснений.

### Рабочая смена

Одна смена длится пять реальных минут. `AdventureShift` учитывает:

- оставшееся время;
- хаос и давление;
- закрытые проблемы;
- деньги и качество;
- условия победы и провала.

Игра должна держать одновременно несколько конфликтующих приоритетов. Игрок
может успеть раньше срока, а может потратить смену на тушение последствий
собственных распоряжений.

### Диалоги и подчинённость

У персонажей есть классы и цепочка подчинения. Руководитель проекта напрямую
ставит задачи прорабу, ГИПу, ГАПу и другим руководителям. Рядовой рабочий может
выполнить прямую просьбу, отправить игрока к своему прорабу или отказаться —
это зависит от дисциплины, лояльности, компетентности и срочности.

Реплики генерируются из роли, состояния, темы и seed персонажа. На площадке
есть короткие фразы, двухсторонние разговоры и командные диалоги с различными
исходами.

### Классы персонажей

Система различает руководителя проекта, заказчика, прораба, подсобника,
электрика, сантехника, монтажника ОВиК, отделочника, проектировщика,
архитектора, ГИПа, ГАПа, инженера и технический надзор.

Класс определяет:

- доступные работы;
- профильную эффективность;
- допустимую непрофильную помощь;
- руководителя;
- форму, каску и визуальные признаки;
- профессиональные реплики и решения ИИ.

Архитектор не начинает долбить стену только потому, что свободен. Электрик
может установить розетку или собрать щит. Подсобник способен помочь с общими
работами, но выполняет профильный монтаж медленнее и хуже.

### Персонажи и внешний вид

`generateCharacter()` детерминированно создаёт персонажа из seed:

- имя и фамилию с учётом визуального пола;
- класс и цепочку подчинения;
- биографию и профессиональную характеристику;
- компетентность, дисциплину, лояльность, энергию и склонность к хаосу;
- внешность, форму, цветовые акценты и поддерживаемые анимации.

Рабочие отличаются лицом, бородой, формой и профессиональным цветом каски.
Прораб носит белую каску. Руководитель проекта, заказчик, архитектор,
проектировщик, ГИП, ГАП и технадзор имеют отдельные силуэты.

### Анимация героя

Герой использует отдельный `HeroLocomotion`:

- восемь направлений движения;
- двенадцатифазный цикл шага;
- старт, ходьбу, бег, поворот, торможение и остановку;
- частоту шага, зависящую от фактической скорости;
- перенос веса, небольшой наклон и вертикальное движение корпуса;
- фиксацию спрайта по нижней опорной точке.

Растровый атлас пока содержит восемь уникальных кадров на направление;
двенадцать фаз используются контроллером движения. Прозрачное смешивание
соседних кадров отключено, потому что оно вызывало мерцание контуров.

### Навигация и ИИ

`NavigationGrid` строит маршрут вокруг стен и оборудования. `CharacterBrain`
выбирает только ту работу, которую разрешает класс, проверяет наличие реальной
рабочей станции и ведёт персонажа по маршруту. Анимация сверления не запускается
посреди пустого коридора: необходим объект типа `wall`, `socket`, `panel` или
другая подходящая станция.

Свободный персонаж может ждать, разговаривать или бездельничать. Его состояние
не должно подменять настоящую производственную задачу бесконечным блужданием.

### Квесты, предметы и навыки

`GameState` хранит квесты, цели, инвентарь, экипировку, навыки, опыт и деньги.
Предмет работает только после получения и экипировки. Например, поверенная
рулетка изменяет результат обмера, но не выдаёт бонус, пока лежит в ящике.

Журнал объединяет:

- текущие задачи;
- навыки и очки развития;
- «куклу» героя и экипировку;
- деньги и состояние стройки.

### Снабжение и экономика действия

Заказ материала или изделия — игровое решение. Для двери игрок вводит размер,
платит из кассы и получает физический объект только после правильного заказа и
доставки. Ошибка размера тратит время и не продвигает квест.

### Чат стройки

Чат визуально повторяет мобильный строительный мессенджер. В него бесконечным
потоком приходят процедурные сообщения от участников. Сообщения игрока могут
ускорить реакцию, испортить отношения или остаться единственным документом,
который кто-то действительно прочитал.

## Процедурная площадка

Генераторы используют детерминированный seed, поэтому один объект можно
воспроизвести в тесте.

`spatial-generator.js` создаёт:

- помещения логичных офисных типов;
- стадии `shell`, `demolition`, `rough`, `engineering`, `finish`, `furnished`;
- наполнение для каждой стадии;
- связанные пространственные задачи;
- события, подходящие текущему состоянию комнаты.

`adventure-site-generator.js` превращает результат в проходимую площадку с
функциональными зонами, точками взаимодействия и маршрутами. Сейчас генераторы
уже используются как каркас движка, но первая глава всё ещё частично собрана
вручную для контроля драматургии и качества.

## Экономический симулятор компании

Главный контур `GameSaveV2` поддерживает до трёх активных объектов и единый
календарь компании. Каждый проект хранит собственные работы, график, договор,
финансы, материалы, документы, изменения заказчика и режим делегирования.

### Портфель и делегирование

- `manual` — решения принимает игрок;
- `supervised` — команда работает в заданных пределах и эскалирует отклонения;
- `autonomous` — назначенный руководитель проекта ведёт объект в фоне.

Сотрудник назначается на один основной объект в день. Экстренный перевод
отнимает время, повышает стресс и прекращает его влияние на старой площадке.
Фоновый объект использует ту же формулу производительности, что и открытая
сцена.

### Ресурсный график

График связывает:

- технологическую задачу;
- срок и зависимости;
- ответственного сотрудника компании;
- подрядчика и численность его бригады;
- материалы и документы;
- плановый платёж и фактическое выполнение.

Завершённая работа больше не появляется в ежедневном плане. Приоритеты меняют
распределение ресурсов, а перегруженная маленькая площадка получает штраф за
тесноту.

### Подрядчики

Подрядчики отличаются профилем, ценой, скоростью, качеством, численностью,
уровнем и отношением к компании. Их можно усиливать, сокращать, менять и
снимать вечером. Новая бригада выходит не мгновенно.

Завершившая работу бригада не исчезает автоматически: ожидание тоже входит в
ежедневное содержание. Игрок должен провести вечернее закрытие, рассчитаться
или оставить долг. Неоплата ухудшает отношения и со временем создаёт судебную
претензию.

### Приёмка и переделки

Выполненную работу нужно предъявить. Вероятность приёмки зависит от качества,
подрядчика и контроля команды. Отказ создаёт дефект и переделку. Строить поверх
непредъявленной работы иногда быстрее, но такой объём не создаёт этапный платёж
и повышает риск финального отказа.

Финальное удержание заказчика блокируется до сдачи исполнительной
документации.

### Деньги

Экономика ведётся проводками. Деньги не возникают от изменения цифры в
интерфейсе.

- Аванс поступает в кассу, но не считается прибылью.
- Принятая работа создаёт дебиторскую задолженность.
- Заказчик платит по условиям договора через несколько дней.
- Подрядчики получают аванс, промежуточное закрытие и финальное удержание.
- Зарплата, офис, материалы, аутсорсинг и кредиты создают обязательства.
- Кредит можно взять во время проекта; ежемесячный платёж списывается по
  календарю.
- Прибыльный объект всё равно способен создать кассовый разрыв.

Компания хранит дебиторку, кредиторку, резерв, долги и тридцатидневный прогноз
денег. Просрочки снижают мораль, останавливают подрядчиков, блокируют поставки
и портят репутацию.

### Люди и штаб

Постоянный штат — «скелет» компании, подрядчики — «мышцы». Сотрудники имеют
зарплату, уровень, навыки, сильные стороны, слабость, стресс, настроение,
лояльность и историю проектов. Они получают опыт от реальной работы, могут
выгорать, конфликтовать, просить повышение или увольняться.

Штаб развивается как внутренний многодневный проект. Дерево улучшений даёт
измеримые бонусы к контролю затрат, снабжению, фоновому управлению, обучению и
кредитному лимиту. Артефакты руководителя экипируются через «куклу» и работают
только после открытия.

### Изменения и события

Изменение заказчика создаёт настоящий `ChangeOrder`: новые или удалённые
работы, зависимости, стоимость, срок и источник финансирования. Игрок может
оформить дополнительное соглашение, начать за свой риск, отказаться,
переложить объём на подрядчика или воспользоваться редкой кнопкой «Порешать».

Крупные события ограничены дневным ритмом и привязаны к состоянию объекта.
Локальные ситуации возникают у конкретных людей и фронтов. События бывают не
только плохими: заказчик может согласовать допработы, увеличить срок или
раньше оплатить этап.

| `office-generator.js` | процедурные композиции офисов |
| `game.js` | интерфейс компании и фасад старого игрового контура |

Лабораторные страницы в `prototypes/` нужны для разработки отдельных систем и
не считаются самостоятельными игровыми режимами.

## Локальный запуск

Требуется современная версия Node.js.

```bash
npm install
npm run dev
```

Открыть:

- `http://127.0.0.1:4173/` — вход и главное меню;
- `http://127.0.0.1:4173/prototypes/fitout-chapter-one.html` — игровая глава
  напрямую.

Не открывайте прототипы через `file://`: браузер блокирует ES-модули и загрузку
ассетов.

## Проверки

Быстрые тесты:

```bash
npm test
```

Полный релизный контур:

```bash
npm run test:release
```

Он выполняет:

1. unit- и integration-тесты;
2. аудит проходимости экономики;
3. миграцию старого сохранения в `GameSaveV2`;
4. production-сборку Vite;
5. аудит npm-зависимостей;
6. проверку API сохранений на временной базе.

Дополнительные команды:

```bash
npm run audit:economy
npm run smoke:migration
npm run build
npm run preview
npm run smoke:public
```

## Сохранения

Клиент использует `GameSaveV2`. API находится в `server/server.py` для
production и `server/server.mjs` для локальной Node.js-версии. Публичный префикс
API — `/fg-api`.

Старое одиночное сохранение мигрирует без потери текущего объекта. Проверка
миграции входит в обязательный релизный контур.

## Production и деплой

Публичный адрес: [https://fitout.ovc.me/](https://fitout.ovc.me/).

```bash
npm run deploy
```

Штатная выкладка:

1. запускает релизные проверки;
2. создаёт резервную копию базы игроков;
3. загружает статическую сборку в новый версионированный каталог;
4. проверяет и перезапускает API сохранений;
5. атомарно переключает активную версию;
6. выполняет публичный smoke-тест;
7. возвращает предыдущую версию при ошибке после переключения.

Адреса серверов, SSH-параметры, внутренние пути, порты и имена сервисов в
публичном README намеренно не приводятся. Они задаются окружением развёртывания
и хранятся отдельно от пользовательской и игровой документации.

## Что ещё не готово

- Первая глава пока частично собрана вручную и не создаётся целиком из
  генератора пространств.
- Не все классы имеют полный набор восьминаправленных анимаций.
- У героя восемь уникальных растровых кадров на направление, хотя контроллер
  уже рассчитывает двенадцать фаз.
- Экономический контур компании и ходячая площадка ещё не объединены в одну
  непрерывную кампанию.
- Полноценный сюжет пока представлен первой учебной главой.
- Телефонный интерфейс намеренно отключён; поддерживаются компьютер и iPad.

Актуальные отложенные задачи находятся в [`docs/BACKLOG.md`](docs/BACKLOG.md).
